## 使用指南

### 如何选择模板

1. **开发新功能** → 使用 `feature-implementation.md`
2. **重构代码** → 使用 `refactor-plan.md`
3. **修复 Bug** → 使用 `bug-fix.md`
4. **变更设计** → 使用 `change-request.md`
5. **迁移代码** → 使用 `migration-plan.md`

### 使用步骤

1. **复制模板**
   ```bash
   cp <workspace>/roleflow/blueprints/template/implementation/[template-name].md \
      <workspace>/roleflow/implementation/[version-or-batch]/[document-name].md
   ```

2. **填写内容**
   - 替换所有 `[占位符]` 为实际内容
   - 填写所有必要章节
   - 删除不适用的可选章节
   - 更新日期、版本、批次等元信息

3. **持续更新**
   - 在实施过程中持续更新文档
   - 记录实际进度和遇到的问题
   - 标记 TODO 列表的完成状态

4. **归档**
   - 工作完成后更新最终状态
   - 添加总结和经验教训
   - 保留文档作为历史记录

## 模板结构说明

### 元信息区

每个模板开头都包含元信息：
- **创建日期**: 文档创建时间
- **负责人**: 主要负责人
- **状态**: 当前状态标记
- **相关信息**: Issue、需求文档、规格说明等链接

### 核心章节

所有模板都包含的核心章节：
- **目标/背景**: 说明为什么要做
- **方案设计**: 说明怎么做
- **TODO 列表**: 任务清单
- **风险评估**: 潜在风险
- **进度跟踪**: 实施进度

### 可选章节

根据实际情况可删除的章节：
- 不相关的边界情况
- 不适用的测试场景
- 简单项目不需要的风险评估

## 最佳实践

### 1. 及时更新

✅ **推荐**：
- 实施过程中持续更新
- 遇到问题立即记录
- TODO 完成后立即标记

❌ **避免**：
- 项目结束才补写文档
- 文档与实际严重脱节

### 2. 保持简洁

✅ **推荐**：
- 使用列表和表格
- 简明扼要的描述
- 删除冗余内容

❌ **避免**：
- 过长的段落叙述
- 不必要的细节
- 重复的信息

### 3. 结构清晰

✅ **推荐**：
- 使用清晰的标题层级
- 适当使用代码块
- 添加流程图和示意图

❌ **避免**：
- 混乱的章节结构
- 缺少代码示例
- 纯文字描述复杂流程

## 文档大小限制

根据 Archivist 角色定义:
- **普通实现文档**: ≤ 12KB
- 超出限制时应拆分为多个子文档
- 如无法拆分,需向用户申请提高限制

## 维护规则

### 创建新文档时

1. 复制相应模板
2. 重命名为有意义的文件名
3. 放入对应版本目录 (如 `4.8.0/`)
4. 填写完整的元信息

### 更新文档时

1. 更新 "最后更新" 日期
2. 在 "更新说明" 中记录变更
3. 保持文档版本递增 (v1.0 → v1.1 → v2.0)

### 归档文档时

1. 标记状态为 "Completed"
2. 填写完成日期
3. 添加总结章节
4. 保留在 implementation 目录
