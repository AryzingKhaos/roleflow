# 高保真交互原型模板

> 本文件是 `prd-designer` 角色的产物模板：为规范化 PRD 配套产出可在浏览器直接打开的高保真 HTML 交互原型时，按本模板组织目录、页面与配套文档。
> 原型的定位是**评审与验收的可视化事实源**：页面布局与视觉层级以原型为准，规则文案与变量口径以 PRD 明细章（§6）为准（裁决关系写在 PRD §12.2）。
> **视觉规范**：本模板只管结构与交互；配色、字体、组件规格见设计规范——默认 `./design-spec.md`（基底样式 `./design-assets/`），用户调用时传入新设计规范则以传入的为准。

## 1. 目录结构

```text
<任务目录>/raw/
  prototype/
    _shared-assets/            # 跨功能共享静态资源（字体、logo、图标、代币图等）
      fonts/
      logos/
      icon-*.svg
    <feature-slug>/            # 一个功能一个目录，英文 kebab-case（如 tx-confirm-parsing）
      <总览>.html              # 评审唯一入口
      <分类A>-<feature>.html   # 分类页：按业务链路 / 场景分组，一组一页
      <分类B>-<feature>.html
      <场景底座>.html           # 单场景高保真页，被分类页以 iframe 引用
      <shared>.css / <shared>.js  # 本功能共享样式与交互脚本
      <feature>-模板与主文案.md  # 文案对照文档（见 §4）
      <feature>-产品主流程.md    # 原型视角的主流程说明（可选）
      <场景需求>-*.md           # 单场景的需求说明（可选，逐场景）
  flowcharts/                  # 流程图源（HTML）与导出图（PNG）成对存放
```

命名约定：
- 目录用英文 kebab-case；页面文件名用「<分组中文名>-<feature>-<页面类型>.html」，让文件列表可读。
- 流程图、结构标注图放 `flowcharts/`（HTML 源 + PNG 成对），不混进 `prototype/`。

## 2. 页面类型与职责

| 页面 | 职责 | 必备内容 |
|---|---|---|
| 总览页 | 评审唯一入口 | 顶部导航（总览 + 各分类页 + 版本标签）；hero 区（功能名、一句话机制、关键数量指标）；规则 / 场景总表（每行链接到对应分类页的具体场景）；业务链路卡片（每条链路的步骤序列 + 入口链接） |
| 分类页 | 一条业务链路 / 一组场景 | 同一套顶部导航；左侧场景切换列表；页面上方展示本链路步骤序列并**高亮当前场景**；主区以 iframe 加载场景底座 |
| 场景底座页 | 单场景 1:1 高保真还原 | 目标界面的真实尺寸、布局、字体、配色与文案；只承载单场景，被分类页引用，不直接作为评审入口 |

## 3. 交互与实现约定

- **场景寻址**：分类页支持 `?scene=<场景id>` 查询参数直达场景，总览页总表的行链接按此拼接（如 `<分类页>.html?scene=r09`），保证 PRD 与评审纪要可精确引用到场景。
- **导航一致**：所有总览 / 分类页共用同一条顶部导航与当前页高亮，评审时可在链路间来回跳转。
- **先定载体**：产原型前先确认目标载体（扩展弹窗 / 移动 App / PC Web / 其他），选设计规范的对应载体预设；需求未写明就问用户。分类页的中部舞台按载体放对应设备帧（弹窗卡片 / 手机帧 / 浏览器帧或全宽整页）。
- **高保真标准**：
  - 尺寸与目标载体一致（弹窗按真实弹窗宽高、移动 App 按手机帧、PC Web 按设计宽呈现）；
  - 文案用 PRD §6.1 的**真实样例取值**（占位符代入后的实际文案），不用 lorem / 假数据；
  - 状态完整：正常态之外，骨架 / 加载、降级 / 兜底、异常提示等 PRD 定义过的形态都要有对应场景；
  - 静态资源全部本地化到 `_shared-assets/` 或功能目录内，**不引用外部 CDN / 网络字体**，离线双击可打开。
- **样式与脚本收敛**：分类页共用的布局、导航、链路高亮逻辑抽到本功能的共享 css / js，场景底座只保留自身样式。

## 4. 配套文档：`<feature>-模板与主文案.md`

原型必须配一份文案对照文档，作为「原型 ↔ PRD ↔ 外部配置表」三方核对的桥梁，包含：

1. **原型入口与分组**：总览页路径 + 表格「分组 | 分类页文件 | 建议演示顺序 | 覆盖的规则行（R-xx）」。
2. **易混场景对照**：同名 / 相近场景的区分表（入口、口径、验收差异）。
3. **展示分工口径**：本功能与相邻需求 / 区域的展示分工要点（逐条短句）。
4. **规则终态总表**：与 PRD §6 对齐的逐行终态快照（识别条件 / 变量来源 / 用户展示 / 覆盖结论）。
5. **变量完整性与降级**：各行必需变量与缺失处理对照。
6. **原型底座清单**：场景底座文件列表及其被哪个分类页引用，声明「评审入口以分类页为准」。

## 5. 与 PRD 的一致性门禁

交付前逐项自检：

- [ ] PRD 顶部元信息的「产品原型（HTML）」链接指向总览页，且相对路径可达；
- [ ] PRD §6 的每个 R-xx 行都能在原型中找到对应场景（总览表行链接可直达）；
- [ ] 原型文案与 PRD §6.1 逐字一致（含占位符代入值）；不一致时按 PRD §12.2 以错误一侧回改并记变更记录；
- [ ] PRD 定义的骨架 / 兜底 / 异常形态在原型中有对应场景；
- [ ] 全部页面离线双击可打开，无外部网络依赖。
