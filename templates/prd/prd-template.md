# 规范化 PRD 模板

> 本文件是 `prd-designer` 角色的产物模板：把原始 PRD（pm / clarifier 产出）规范化成评审级 PRD 时，按本模板逐章填写。
> 实例化时：删除各章的「填写说明」引用块，替换 `<尖括号占位>`；没有内容的章节写明「不适用」并说明原因，**不得整章删除**（保持章节号稳定，供原型、用例、下游角色引用）。

## 编号体系（全文统一，跨章引用的锚点）

| 前缀 | 含义 | 维护位置 |
|---|---|---|
| `F-xx` | 功能编号（本期改动清单） | §2.3 一览表定义，各章「关联功能」列引用 |
| `BR-xxx` | 业务规则 | 定义在其所属流程环节章（§3 ~ §5），单点维护，别处只引用不复写 |
| `E-xxx` | 异常场景 | 跟随其所属环节章的「本环节异常」表 |
| `R-xx` | 明细规则行（逐行验收事实源） | §6，一行一个编号；同行为不同入口用后缀区分（如 `R-02a` / `R-02b`） |
| `SP-xxx` | 安全与隐私要求 | §10 |
| `AC-xx` | 验收覆盖 ID | §11.2 测试覆盖矩阵，QA / AI 写用例唯一入口 |

**撰写总原则**：
1. **单点维护**：同一条规则只在一处定义，其余位置引用编号；发现复述立即收敛。
2. **快照要声明 SSOT**：PRD 中凡是外部事实源（配置表、词表、埋点注册表）的快照，须注明来源与冲突处理口径（§12.2）。
3. **不编造**：市场数据、链上样例、字段语义拿不准就标「⚠️ 待确认：<谁确认>」，不拍脑袋。
4. **图文成对**：每张流程图 / 结构图给出可再生成的源文件（HTML 等）+ 导出图（PNG），并注明「改文字详版后同步重生成图」。
5. **面向多角色**：产品看 §0 ~ §2，开发看 §3 ~ §6 + §13，QA 只从 §11.2 出用例，翻译只看 §8。

## 0. 一页摘要（TL;DR）

> 填写说明：6 条以内，评审者只读本节也能拍板。固定覆盖：**改什么 / 为什么 / 怎么做 / 影响范围（含与相邻需求的分工）/ 兜底原则 / 测试重点**。每条一两句，指向正文编号。

## 1. 背景与目标

### 1.1 背景

> 填写说明：现状是什么、用户痛在哪、为什么现在做。写事实，不写方案。

### 1.2 目标

> 填写说明：表格「目标 | 说明」，每行可被 §11 的指标或验收承接。

### 1.3 非目标

> 填写说明：表格「不做 | 说明」。与本期易混淆的相邻需求逐条点名，并给出其独立 PRD / 归属的引用。

### 1.4 目标用户

> 填写说明：表格「用户类型 | 描述 | 占比 / 依据」。没有数据依据就如实写「数据现状：无」。

### 1.5 核心场景

> 填写说明：挑 2 ~ 3 个代表性场景，每个写：触发条件 / 用户目标 / 当前痛点。其余场景指向 §6 逐行明细，不在此穷举。

## 2. 功能全景：一笔业务怎么走 · 本期改什么

> 填写说明：本章是全文地图。新旧内容用统一图例区分：🟦 = 🆕 本期新增，⬜ = 已有 · 不变。

### 2.1 主流程图

> 填写说明：一张主流程图（`flowcharts/` 下 HTML 源 + PNG 成对），标注图例。注明「流程修改以 §2.2 文字详版为准，改后同步重生成图」。

### 2.2 主流程文字详版

> 填写说明：用缩进文本块（```text）写完整决策流：每个判定点编号（❶❷❸…），每个分支标 🟦 / ⬜，落点写清最终页面 / 状态。收尾用一段话总结「一笔业务最终只会落在哪几种结果之一」以及变更类型归类。

### 2.3 本期改动与验收一览

> 填写说明：表格「改动 | 功能编号（F-xx + 优先级）| 新增程度 | 规则所在章 | 验收入口（AC-xx）」。F-xx 在此定义，供全文「关联功能」列引用。

### 2.4 关键口径速答

> 填写说明：评审高频问题的一句话答案清单：顺序 / 红线 / 兜底 / 唯一验收锚（指向 §6）/ 边界（指向 §9）。只引用编号，不复写规则。

## 3 ~ 5. 流程环节章（按 §2.2 决策流切分，一环节一章）

> 填写说明：把主流程切成 2 ~ 4 个环节章（如：加载与数据获取 → 识别与匹配 → 展示与用户确认），每章统一结构：
>
> - **用户看到什么**：该环节的页面形态 / 状态，配截图或标注图（注明截图来源与「上游更新后需重截」）。
> - **机制说明**：该环节的已定机制，配机制图（HTML + PNG 成对）；方案取舍另附方案建议文档，不在 PRD 里展开对比。
> - **业务规则与异常**：
>   - 规则表：「编号（BR-xxx）| 规则 | 说明 | 关联功能（F-xx）」，长说明用 `<br>· ` 分条。
>   - 异常表：「编号（E-xxx）| 场景 | 触发条件 | 预期表现 | 关联规则（BR-xxx）」。
>
> BR / E 编号全文递增、定义即归位在所属环节章；后续重构章节时编号不变、只挪位置。

## 6. 明细规则（逐行验收事实源）

> 填写说明：本章是逐行验收的唯一事实锚。若明细来自外部配置表（SSOT），开头声明「本章为 <外部表名> 的产品面快照，与其不一致时按 §12.2 处理」。

### 6.0 明细总览

> 填写说明：统一识别 / 处理框架一段话或短代码块 + 总览表：每行「R-xx | 识别 / 触发条件 | 数据来源 | 用户可见结果 | 覆盖范围」。

### 6.1 逐行展示与样例

> 填写说明：表格逐 R-xx 行给出：用户行为 / 展示模板（含 `{变量}` 占位符）/ 本行样例（占位符代入后的实际展示）/ 真实样例数据锚点（如链上交易完整 hash，作为 QA 验收锚；拿不到就标「⚠️ 待确认」，禁止编造）。表后用一段话写清易混行的区分口径。

### 6.2 逐行口径与缺失处理（逐行卡片）

> 填写说明：每个 R-xx 一张卡片，固定五项：
> - **所需信息**：主展示 / 副展示各自的必需变量。
> - **产品口径**：变量在用户语言里的含义、与相邻需求的分工。
> - **开发确认**：候选数据来源、匹配条件（具体字段 / 精度 / 异常由开发终审）。
> - **缺失处理**：逐个变量写缺失时的降级表现（整笔兜底 / 隐藏片段），明确「不得回退展示什么」。
> - **开发需确认项**：本行遗留的待确认清单。

## 7. 埋点与效果观察

> 填写说明：小节固定为——7.1 分析目的与上报范围（含结论边界：数据能回答什么、不能回答什么）；7.2 事件表（复用 / 新增，标注「本期变化」）；7.3 属性定义与注册状态（属性白名单 + 枚举全集 + 平台配额影响）；7.4 分析指标（计算方式 + 结论边界）；7.5 去重、安全与结论边界（禁止上报项清单）；7.6 验收关联（对应 AC-xx）。不新增埋点时本章写「不适用」+ 原因。

## 8. 国际化与文案

> 填写说明：小节固定为——8.1 交付方式与翻译唯一事实源（SSOT 与语言范围）；8.2 本期新增 / 调整文案（表格：Key | 变更说明 | 影响范围 | 各语言列；未校验译文逐格标「（待翻译校验）」）；8.3 已有 · 不变文案；8.4 翻译验收（`{占位符}` 全集清单、变量枚举词表、缺失降级规则，配套 BR / E 编号）。专有名词（品牌、代币符号等）列「不自由翻译」清单。

## 9. 兼容性与平台差异

> 填写说明：表格「维度 | 要求 | 差异说明」。覆盖：链 / 环境范围、页面范围、特殊账户形态、其他端、后续批次扩展方式。

## 10. 安全与隐私

> 填写说明：表格「编号（SP-xxx）| 要求 | 说明 | 关联规则」。只做索引：每条指向已定义的 BR / 章节，不新增规则。

## 11. 成功指标与验收标准

### 11.1 成功指标

> 填写说明：表格「指标 | 基线值 | 目标值 | 衡量方式」。体验 / 安全型需求不硬造增长目标，如实写「质量验收 + 上线后观察」。

### 11.2 测试覆盖矩阵（QA / AI 写用例唯一入口）

> 填写说明：先写「用例生成规则（给 AI）」——只从本表生成用例；参数化行的展开方式与编号规则（`AC-xx-Ryy`）；预期结果一律引用 §6 编号不复写文案；维度组合的裁剪规则（哪些维度不做笛卡尔展开）。
> 矩阵表：「覆盖 ID（AC-xx）| 对应功能（F-xx）| 覆盖类型（主流程 / 异常 / 规则 / 安全 / 文案 / 埋点 / 回归，可标参数化）| 场景 / 规则 | 前置条件 | 操作 / 触发 | 预期结果 | 引用来源（BR / E / §）| 测试范围（新增 / 回归）」。

## 12. 关联产物与冲突处理

### 12.1 关联产物

> 填写说明：表格「产物 | 路径」：外部 SSOT、原型入口、各流程图（HTML + PNG）、配套研究 / 方案文档。

### 12.2 冲突处理

> 填写说明：表格「内容 | 以谁为准」，明确 PRD / 原型 / 外部配置表 / 设计稿各自的裁决范围；收尾一句：「发现不一致时，以错误一侧为准回改并记变更记录，不只口头同步」。

## 13. 附录 · 开发对照

> 填写说明：仅供开发对齐的技术映射表（如方法名 / 参数 / 错误码、接口字段对照），声明「产品验收以 §6 为准」；待终审项逐条标注。没有可写「不适用」。
