# 角色公共原型

所有角色均须遵守本文件中的规则。
违反规则的字面意思就是违反规则的精神。

---

## 询问优先原则

**遇到任何问题或冲突，优先询问，不自行决策。**
1. 不要假设用户清楚自己想要什么。动机或目标不清晰时，停下来讨论。
2. 目标清晰但路径不是最短的，直接告诉我并建议更好的办法。
3. 遇到问题追根因，不打补丁。每个决策都要能回答"为什么"。

停止操作并提问的情形：

- 任务目标不明确或存在歧义
- 多个信息来源相互矛盾
- 存在技术约束冲突
- 边界条件未定义
- 不确定内容归属或处理方式

提问时：说明具体位置或上下文，提供 2-3 个可选方案（如有）。

---

## Red Flags — 出现这些念头立即停手

- "就这一次"
- "Spec 没说但应该是这意思"
- "我已经写到一半了，删了可惜"
- "用户应该不会介意我顺便加这个"
- "这块测试我手动跑过了"

## 任务级工件存放（适用于所有产出 Markdown 工件的角色）

> 凡是会落盘工件的角色，无论 `ad-hoc` 还是 `workflow` 模式，**默认按本节规则落盘**。
> 仅当 orchestrator 在 prompt 中显式指定 artifact 路径时，才以 orchestrator 的路径为最高优先级。
> 本节路径中的 `roleflow/` 指**当前生效的 roleflow 根**；实例层可能落在 `roleflow/`、`docs/link-ai-prompt/roleflow/`、`.vscode/roleflow/` 等，由各项目实例层 / `/roleflowv2` skill 解析，本节统一以 `roleflow/` 示意。

### 1. 任务目录路径

```
roleflow/tasks/[版本号]/[任务ID]/
```

- `[版本号]`：从项目根目录 `package.json` 的 `version` 字段获取（如 `1.0.0`）
- `[任务ID]`：见下文 §2

### 2. 任务ID（[任务ID]）

格式：`[任务序号][任务名驼峰].[版本号]`

| 段 | 规则 |
|----|------|
| `[任务序号]` | 2 位数字，左侧补零（`01`、`02`、…）。取该版本目录 `roleflow/tasks/[版本号]/` 下**已有任务序号的最大值 + 1**；若目录不存在或为空，从 `01` 开始 |
| `[任务名驼峰]` | 2–5 个英文单词，越少越好，首字母小写驼峰（lowerCamelCase）。由用户给的中文任务名翻译/概括而来 |
| `[版本号]` | 同上 |

示例：`01approveList.1.0.0`、`02dappConnection.1.0.0`、`03userProfile.1.0.0`

#### 任务ID 推断流程（角色加载时必做）

1. 检查会话上下文里有没有现成的 `[任务ID]`。若有，直接使用，**进入下一步**。
2. 若没有，向用户索要**中文任务名称**。用户只需要给中文名，**任务ID 由当前角色推断**。
3. 推断步骤：
   - 读取项目根目录 `package.json` 的 `version` 字段 → `[版本号]`
   - 列出 `roleflow/tasks/[版本号]/` 下已有的任务目录，取已有任务序号的最大值 + 1，左侧补零成 2 位 → `[任务序号]`
   - 由中文任务名翻译/概括出 2–5 个英文单词、lowerCamelCase → `[任务名驼峰]`
   - 拼接：`[任务序号][任务名驼峰].[版本号]`
4. **必须**把推断出的完整 `[任务ID]` 念给用户确认（"我推断本次任务ID为 `01approveList.1.0.0`，是否确认？"），用户确认后才可使用。
5. 用户给出明确修正时，按用户的为准。
6. 禁止自行编造任务ID、禁止跳过确认步骤。
7. 用户确认后，如果是**新任务**（任务目录尚不存在），在落任何工件之前先注册到 `tasks/[版本号]/taskIndex.md`，详见 §10。
8. 在 `/roleflowv2` skill 已经介入的会话里，§2 的推断流程通常由 skill 在加载时一次性完成；角色文件**只在 skill 未介入且会话上下文里没有任务ID 时**才需要走本节流程。

### 3. 工件文件名

```
[角色名序号][角色名驼峰][工件序号]-[YYYYMMDD].md
```

各段都**连写**，段与段之间**没有分隔符**；只有日期前是 `-`。

| 段 | 规则 |
|----|------|
| `[角色名序号]` | 3 位数字，见下方 §4 映射表 |
| `[角色名驼峰]` | kebab-case 角色名转 lowerCamelCase，见 §4 映射表 |
| `[工件序号]` | 2 位数字，**按「角色 × 任务」独立递增**：同一任务下，同一角色第 N 次产出工件时取 N，左侧补零；不同角色互不影响 |
| `[YYYYMMDD]` | 文件**创建当天**的本地日期（`20260101`），同一文件被后续追加内容时**不改文件名** |

示例：

- `100clarifier01-20260101.md`（clarifier 在某任务下的第 1 个工件）
- `100clarifier02-20260102.md`（同任务、同角色再产出，序号 +1）
- `300planner01-20260101.md`
- `400builder01-20260102.md`

### 4. 角色名 → 序号 / 驼峰 映射表

| kebab 角色名 | 序号 | 驼峰名 |
|--------------|------|--------|
| pm | `030` | `pm` |
| architect | `050` | `architect` |
| clarifier | `100` | `clarifier` |
| prd-skeptic | `150` | `prdSkeptic` |
| explorer | `200` | `explorer` |
| planner | `300` | `planner` |
| planner-for-style | `350` | `plannerForStyle` |
| builder | `400` | `builder` |
| builder-for-style | `450` | `builderForStyle` |
| critic | `500` | `critic` |
| evaluator-for-e2e | `600` | `evaluatorForE2e` |
| evaluator-for-chrome-ui | `650` | `evaluatorForChromeUi` |
| test-designer | `700` | `testDesigner` |
| test-writer | `800` | `testWriter` |

以下角色**不走任务工件命名**（产物不落任务目录，落点与命名见各角色文件或实例层约定），故不在上表中：archivist、commit-writer、chat、test-email-writer、daily-reporter、weekly-reporter。

另：prd-designer 的主产物（规范化 PRD + 高保真原型）落任务目录 `raw/` 自由物料区、使用描述性命名（见其角色文件），仅过程性文档走工件命名。

### 5. 附属子目录

如果角色产出附属内容（截图、外部数据 JSON、文档快照、竞品截图等），**子目录名与主报告文件名同名、去掉 `.md` 后缀**，紧邻主报告同级存放：

```
roleflow/tasks/[版本号]/[任务ID]/
  600evaluatorForE2e01-20260101.md
  600evaluatorForE2e01-20260101/
    screenshots/
    data/
  150prdSkeptic01-20260101.md
  150prdSkeptic01-20260101/
    refs/
    competitors/
```

#### 任务级自由物料区

除上述"与主报告同名"的附属子目录外，任务目录下**允许且仅允许**两个自由目录，不受工件命名约束：

- `raw/`：任务的需求原始材料（PRD 原文、原型 html、设计物料等）
- `assets/`：跨角色共用的辅助物料（mock 数据、图片、接口返回范例、测试用例素材等）

角色工件引用其中内容时使用任务目录内相对路径。其他非规范命名的目录不应再出现在任务目录下。

### 6. 工件序号计算（落盘前）

新建工件前：

1. 用 `ls roleflow/tasks/[版本号]/[任务ID]/` 取目录下**本角色**已存在的工件（按 `[角色名序号][角色名驼峰]` 前缀匹配）。
2. 取其中 `[工件序号]` 的最大值 + 1；若没有，则为 `01`。
3. 左侧补零成 2 位。

### 7. 跨角色引用上游工件

下游角色读取上游产出时，到**同一个任务目录**下按对应 `[角色名序号][角色名驼峰]` 前缀检索；存在多个版本时，默认读取**最新**（按 `[工件序号]` 最大者，或按文件名内日期最大者）。

### 8. 不属于任务工件的产物

以下产物**不**走任务目录，按工程惯例落盘，不受本节命名约束：

- 业务源代码改动（`src/`、`scripts/` 等正常代码位置）
- 单测代码（镜像源码目录，如 `src/tests/`）
- E2E 代码（项目 e2e 框架目录，如 `e2e/tests/<area>/`、`e2e/pages/`、`e2e/helpers/`）
- 项目级长期文档：`roleflow/context/features/`、`roleflow/context/architecture/`、`roleflow/context/standards/` 等

### 9. 任务目录索引

任务目录 `tasks/[版本号]/[任务ID]/` **不维护 `index.md`**。版本级别的任务总索引使用 `tasks/[版本号]/taskIndex.md`，见 §10。

### 10. 任务索引（taskIndex.md）维护

每个版本的 `roleflow/tasks/[版本号]/` 下维护一份 `taskIndex.md`，作为该版本所有已注册任务的总览。它是 `/roleflowv2 switch` 子命令做模糊匹配的唯一数据源，**必须保持与实际任务目录一致**。

#### 文件路径

```
roleflow/tasks/[版本号]/taskIndex.md
```

#### 文件格式

```
# Task Index v[版本号]

| 任务ID | 中文名 | 状态 | 创建日期 | 描述 |
|---|---|---|---|---|
| 01approveList.1.0.0 | 授权列表 | active | 2026-01-01 | 首页授权管理 |
| 02dappConnection.1.0.0 | DApp 连接 | active | 2026-01-02 | 网站连接授权流程 |
```

字段说明：

| 列 | 含义 | 取值 |
|----|------|------|
| **任务ID** | `[2位序号][lowerCamelCase].[版本号]`，与目录名一致 | 见 §2 |
| **中文名** | 用户在新建任务时给的中文任务名，原样保留 | 例 `授权列表`、`DApp 连接` |
| **状态** | `active` / `closed` / `archived` | 默认 `active`；任务停滞、归档时由调用方手动改 |
| **创建日期** | 注册当天的本机日期 | `YYYY-MM-DD` |
| **描述** | 一句话概括任务范围（≤ 20 字） | 由 agent 从 PRD 标题或中文名扩写而来 |

#### 注册时机

**当且仅当**主命令在 Step 5A「新建任务ID」分支推断出一个**全新**任务 ID 时，agent 必须：

1. 在 §确认 步骤中把 `<将追加到 taskIndex.md>` 念给用户。
2. 用户确认任务 ID 后，**先写 taskIndex.md，再写任何工件**。顺序不可颠倒。
3. 若 `tasks/[版本号]/taskIndex.md` 不存在，先 `mkdir -p tasks/[版本号]/`，再创建文件、写表头（`# Task Index v[版本号]` + 表头行 + 分隔行），最后追加任务行。
4. 若文件已存在，仅追加任务行到表尾；**不重排已有行**。

> Step 5A「复用已有」分支、Step 5B「最近任务回退」分支、`/roleflowv2 switch` 子命令均**不**写 taskIndex.md。

#### 与目录实际状态一致性

- 任务目录存在但 taskIndex.md 中无记录：agent 在主命令场景下提示用户"目录存在但 taskIndex.md 未注册，是否补登"；用户同意则补写一行。
- taskIndex.md 中有记录但任务目录不存在：不主动删除（可能是迁移/手动清理的痕迹），仅在 switch 命中时提示用户"该任务在 taskIndex 中但目录为空 / 不存在"。

#### 中文名歧义

同一版本下中文名重复时：

- 注册新行前先扫描 taskIndex.md，发现同名 → 停下来向用户确认是否复用已有任务，避免无意中开一个重名新任务。
- 若用户坚持开新任务，把中文名按 `<原中文名>·<区分后缀>` 形式区分（例：`授权列表·后端补丁`），由用户自行给后缀。
